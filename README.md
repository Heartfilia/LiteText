# LiteText

轻量、原生、跨平台的文本编辑与 HEX 阅读工具，使用 Rust + egui 构建，无需 WebView。

- 多标签文本编辑、大文本分段排版、语法高亮、JSON 格式化与折叠。
- 查找替换、正则搜索、范围标记、空白字符处理和可配置快捷键。
- 只读 HEX 视图、字节选择与 Data Inspector。
- 全局主题、中文／英文界面、从当前文件目录打开终端。
- 未保存内容恢复、外部文件变更保护、GitHub 应用内更新。

## 下载

从本项目的 [GitHub Releases](https://github.com/Heartfilia/LiteText/releases) 下载：

| 平台 | 安装包 | 说明 |
| --- | --- | --- |
| macOS Apple Silicon（M 系列） | `LiteText-macos-arm64.dmg` | 安装和自动更新共用 DMG，不再提供 ZIP |
| Windows x64 | `LiteText-windows-x64.exe` | 单个可执行文件，无需安装器或解压 |
| Linux x64 | `LiteText-linux-x64.zip` | 解压后运行，需要图形桌面环境 |

**目前不提供 macOS Intel／x64 安装包。** 带 `beta`／`rc` 的版本是测试版，首次安装可在 Releases 页面选择；稳定安装版只检查稳定更新，beta／rc 安装版和 `dev` 构建会同时检查稳定版及预发布版本。

每个 Release 附有 `SHA256SUMS`。可计算下载文件的 SHA-256，与同版本清单中的对应项比较：

```sh
# macOS 示例，在下载文件所在目录执行
shasum -a 256 LiteText-macos-arm64.dmg
```

哈希一致只能检查文件完整性，不等同于发布者签名；请确认下载来自本项目仓库。

## 安装与首次启动

### macOS（Apple Silicon）

1. 下载并打开 `LiteText-macos-arm64.dmg`。
2. 将 **LiteText.app** 拖到 **Applications（应用程序）** 文件夹。
3. 弹出磁盘映像，从「应用程序」打开 LiteText，不要长期在 DMG 内运行。

DMG 内附 `安装后打开失败查看.txt`，说明首次启动被拦截时的处理命令、可信来源检查及后续应用内更新方式；说明文件不会自动执行命令。

安装到 `/Applications` 后，也可以在终端启动：

```sh
open "/Applications/LiteText.app"
```

#### 提示无法验证开发者或应用已损坏

当前 macOS 包仅使用 ad-hoc 签名，**尚未使用 Apple Developer ID 签名和公证**，首次打开可能被 Gatekeeper 拦截。可先尝试在 Finder 中右键应用 →「打开」，或在「系统设置 → 隐私与安全性」中查看是否允许打开。

**仅当你已确认安装包来自本项目的可信 Release，并核对文件完整性后**，可以手动移除这一个应用的下载隔离属性，再启动：

```sh
xattr -dr com.apple.quarantine "/Applications/LiteText.app"
open "/Applications/LiteText.app"
```

这里的应用名是 **LiteText.app**，不是 LiteRedis.app。若安装在其他位置，请替换为实际路径（例如 `"$HOME/Applications/LiteText.app"`）。

> 此命令会递归移除该应用的隔离标记，削弱 macOS 对它的首次打开检查，并非修复损坏文件或完成公证。不要对未知应用、整个 Applications 文件夹或系统范围执行，也无需关闭系统 Gatekeeper。若文件校验失败，请重新下载，不要用该命令绕过。

如果提示没有该隔离属性，可以直接尝试打开；如果提示权限不足，请先核对安装位置和当前用户权限，不要盲目添加 `sudo`。应用不会自动执行上述命令。

#### 下载文件夹访问权限再次询问

访问 `~/Downloads` 等受保护目录时，macOS 可能请求“文件与文件夹”权限。可在「系统设置 → 隐私与安全性 → 文件与文件夹」查看 LiteText 的授权。会话恢复和外部修改检查也会访问已打开文件；当前版本仅 ad-hoc 签名，更新／替换 App 或切换启动副本后可能需要重新授权，暂不能保证跨版本保留权限。请固定从 `/Applications/LiteText.app` 启动。上述 `xattr` 命令处理的是下载隔离标记，不会授予此项隐私权限；无需因此反复执行或直接开启完全磁盘访问权限。

### Windows x64

1. 下载 `LiteText-windows-x64.exe`。
2. 放到固定且当前用户可写的目录。
3. 双击 EXE，只显示软件窗口，不附带终端窗口。

若出现 SmartScreen／安全软件提示，请先确认来源；不要为运行未知文件关闭安全软件。应用内更新需要对程序所在目录有写权限，不会自动请求管理员权限。

### Linux x64

在下载文件所在目录解压，并启动：

```sh
mkdir -p "$HOME/.local/opt/litetext"
unzip LiteText-linux-x64.zip -d "$HOME/.local/opt/litetext"
chmod +x "$HOME/.local/opt/litetext/litetext"
"$HOME/.local/opt/litetext/litetext"
```

需要可用的 X11／Wayland 图形会话及 OpenGL 运行库；纯 SSH 无桌面服务器不能直接显示窗口。若缺少动态库，请按发行版安装错误提示对应的运行依赖。当前未提供 deb／rpm／AppImage。

## 基本使用

### 打开、编辑与保存

- 点击欢迎页或右上角菜单中的「打开文件」，也可将文件拖入窗口；支持一次打开多个文件。
- 支持命令行传入多个文件路径；macOS 安装包声明了 JSONL／NDJSON、日志、文本、常见代码和配置文件类型，可通过 Finder「打开方式 → LiteText」打开，应用已运行时也能接收新文件。不会主动修改系统默认应用；如需双击默认使用 LiteText，在 Finder「显示简介 → 打开方式」中选择并点击「全部更改」。替换旧版后请先启动一次新版应用，让系统刷新注册。
- 点击新建图标创建未命名文本，使用标签切换文件；标签可拖动排序，右键可关闭其他标签或打开所在文件夹。
- “未命名”使用当前窗口空闲的最小序号：关闭「未命名 1」后可再次使用 1，所有未命名标签关闭后从 1 开始；普通文件不占用此序号。序号不是临时文件数量。
- 右上角菜单的「新窗口」启动一个没有工作区的独立 LiteText 窗口；顶部新建图标和 Cmd/Ctrl+N 仍创建当前窗口的工作区。各窗口使用独立恢复记录：提前关闭窗口时，仅对关联本地文件的未保存修改弹出保存／放弃／取消，纯临时工作区不弹确认且随该窗口关闭而丢弃。正常退出后，下次只恢复最后关闭窗口的 Tab 和未保存内容，不重新打开提前关闭的窗口；异常退出时最多恢复一份最新会话。
- 标签栏末尾有足够空白时，双击空白区域可新建 Tab；标签挤满或正在拖动时不启用，不影响原有双击标签关闭。
- “打开终端”工具栏按钮默认隐藏；在「系统设置 → 默认终端」上方勾选「工具栏显示打开终端」后显示在原位置，偏好会保存。macOS 终端检测支持 Otty.app。
- **手动保存才会写原文件**。新建文本首次保存时选择位置。
- 应用定期备份未保存内容，重新启动时尝试恢复工作区；恢复记录不是原文件的自动保存，也不能替代重要文件的独立备份。
- 内容缓存只维护仍打开的标签（包括未选中的标签），关闭／放弃标签后立即更新当前会话，不维护已关闭标签的历史版本。启动成功接管恢复记录后退役旧共享／旧窗口内容；正常退出仍保留最后窗口的一份会话，以便下次恢复。重新加载磁盘版本不再另存历史归档，读取／解码失败仍保留当前工作区；旧版可识别的 `before-reload-<id>-<时间戳>.json` 在恢复写入或窗口维护时清理。未知／损坏记录和符号链接目标不自动删除；小型窗口配置／锁文件、最近文件路径、常用设置和更新回滚包不属于文档历史缓存，也不因此清理。此行为不等于磁盘安全擦除。
- 检测到原文件在外部变更时会提示处理，避免直接覆盖。
- 点击右下角文件路径可复制完整地址，上方会显示约 1 秒的「已复制文件地址」提示。

### 编辑工具

- 右上角工具支持查找替换及文本显示选项；搜索按操作执行，可使用正则表达式。
- 「菜单 → 插件 → Format JSON」格式化当前文本，支持撤销；JSON 对象／数组可折叠。
- 「菜单 → 插件」新增 **Format HTML / Format Header / Format Cookie**，离线处理当前激活工作区的全部文本，可一次撤销；失败保留原文，不自动写原文件。成功后语言及左下角显示切换为 HTML／JSON。HTML 使用两空格缩进，保留 `pre` 等空白敏感内容，不执行页面脚本；内嵌 JS/CSS 不另行美化，兼容并保留 `data-cost={"renderCost":"0.4","dataCost":1}` 这类平衡花括号属性。单次限 32 MiB、100000 个 `<` 标记、128 层嵌套，格式化本身仍同步执行。
- 大段粘贴直接进入大文本编辑路径，避免先对全文排版；旧语言的离屏语法前缀解析按帧推进，未完成时暂用普通文字颜色，超过 16 KiB 的单行跳过复杂语法解析。粘贴不会自动改语言或保存原文件，可一次撤销；超大文件／超长单行仍可能有索引和排版开销。
- 查找替换面板的计数行最右侧提供「跳转行」数字输入框与按钮，支持回车；按从 1 开始的逻辑行号跳转到行首，不受自动换行影响。0、越界或数值溢出不执行跳转。
- **Format Header** 支持 `Name: value`、HTTP 请求／状态首行、HTTP/2 伪头及 JSON 对象；值内的冒号原样保留，同名头（不区分大小写）输出数组。
- **Format Cookie** 支持 `a=b; c=d`、`Cookie:`、多行 `Set-Cookie:`、浏览器导出的 JSON `name/value` 数组、JSON 对象和 Netscape cookie jar。`Set-Cookie` 属性不当作 Cookie；值里的 `=` 和百分号不解码，同名 Cookie 输出数组。
- 「菜单 → 插件 → **curl解析**」点击后在工作区上方弹出目标菜单，支持转成 **Python requests、JavaScript fetch、Node.js fetch、Go net/http、Rust reqwest、PHP cURL、HTTP 请求文本**；点击时只转换当前激活工作区，自动切换对应高亮，可一次撤销。
- 「菜单 → 空白符处理」可清理行首／行尾空白、转换 TAB 与空格；状态栏可选择 TAB 输入模式。
- 「菜单 → 文本转换」支持文本转 MD5、文本转 Base64、Base64 转文本、urlencode 和 urldecode；只替换当前激活工作区的全部文本，可一次撤销，不自动保存原文件。MD5 为 UTF-8 字节的小写十六进制摘要；Base64 使用标准编码；URL 转换按 UTF-8 组件编码（空格 `%20`、加号 `%2B`，解码保留字面 `+`）。无效编码或非 UTF-8 解码结果会报错并保留原文。
- 「菜单 → 文本转换 → **url解析**」将单个绝对 URL 输出为 JSON：基础 `url`、`scheme`、`host`、`port`（含协议默认端口）、`path`、`params`、`fragment`。查询参数按表单规则解码（`+` 表示空格，`%2B` 表示加号），重复参数保留为数组；路径和 fragment 保留编码形式。无效 URL／百分号／UTF-8 编码报错，不改原文。
- 状态栏语言选项支持自动识别或手动选择语法高亮；行注释使用当前语言规则。
- `.log` 文件自动使用 **Log** 高亮，也可在语言菜单手动选择：时间戳、数字、字符串、INFO、WARN、ERROR、DEBUG 等分别着色，随全局明暗主题适配；大文件仅分析可见区域，无需扫描全部前缀。
- 双击正文按字符类别选词：连续中文与英文单词分别选中，不包含周围标点；中文按连续汉字选择，不进行词典分词。
- TXT／二进制切换按钮可查看 HEX，HEX 目前用于阅读与选择，不支持字节编辑。
- 正文右侧滚动条始终可见；底部未选中文字时显示光标所在的逻辑行号，选中文字后显示选中字数。
- 工作区正文及 HEX 支持快捷键缩放，字号范围为 **10～32 pt**，偏好自动保存；行号比正文小 1 pt，在对应行内垂直居中。不会缩放菜单和设置界面，自动换行产生的视觉行不改变逻辑行号。行号右键菜单紧凑显示，多行选中时使用「复制内容」，菜单文字不换行。

### cURL 转换范围

原生 Rust 实现参考 [curlconverter](https://github.com/curlconverter/curlconverter) 的“命令 → 请求模型 → 目标代码”流程，**不是完整嵌入上游库，不保证全部语言／参数兼容**，无需 Node.js／Python 运行时。接受 Bash/POSIX 引号和反斜杠续行；支持单个 HTTP(S) URL、`-X`、`-H`、`-b` Cookie 字符串、`-u user:password`、User-Agent、Referer、`--data` / `--data-raw` / `--data-binary` / `--data-urlencode` / `--json`、`-G`、`-I`、`-L`。请求正文以字面 UTF-8 保留，JSON 不重新解析为目标对象。

转换时**不执行 shell、不发请求、不读取 `@file` 或 stdin**。不支持的参数（如 multipart、代理、`--compressed`）、动态 shell 表达式、多个请求及不能准确表示的组合会报错，不会悄悄忽略；Python/fetch 无法忠实表示的重复头会拒绝，fetch 的 GET/HEAD 正文会拒绝。浏览器 fetch 还受 CORS、禁用请求头和浏览器 Cookie 规则限制；生成的代码需要用户在对应环境自行运行，敏感 Cookie／凭据会原样包含在结果中。

### 打开终端

打开工作区后，顶部查找替换与 TXT／二进制切换之间显示终端图标：

- 已保存文件：从文件所在目录打开终端。
- 未命名文本或解除文件关联的副本：从当前用户主目录打开。
- 「系统设置 → 默认终端」可选择检测到的终端或自定义程序路径；填写程序路径，不是 shell 命令。
- macOS 的「系统默认」使用 Terminal；选择 iTerm2 也可打开。首次调用可能需要系统「自动化」权限，拒绝后可在「系统设置 → 隐私与安全性 → 自动化」中检查授权。

### 设置与快捷键

「系统设置」支持界面语言、默认终端、全局主题、快捷键和更新代理。设置即时生效，无需点击「完成」；可用右上角关闭按钮或 Esc 返回。

快捷键配置页仅显示文件与标签页、基础编辑、查找替换，不再展示 HEX 工具配置；已有 HEX 操作和快捷键仍保留。底部 TAB 模式菜单等宽居中显示。插件 cURL 解析使用随主题切换的语言卡片，窄窗口自动单列，可滚动查看；转换仍仅作用于当前文本工作区，可撤销，不执行命令或发起网络请求。

设置按通用、终端、外观／快捷键和应用更新分组；复选框和按钮使用独立的清晰边框，支持深浅主题。更新按钮、安装提醒和状态文字分行显示，长消息自动换行，小窗口可滚动查看。

**常用配置会自动记住，不需要每次升级重新勾选。** 语言、主题与配色、工作区字号、TAB 模式、终端选择／自定义路径／工具栏开关、快捷键、更新代理和 HEX 显示偏好独立保存到应用数据目录的 `preferences.json`，不放在安装包内，也不包含文档内容。修改后约 0.5 秒自动保存，关闭设置、退出或安装更新前会立即保存；旧版配置会在首次启动时迁移。多个窗口中未改配置的窗口不会覆盖其他窗口新保存的偏好。

替换 App／EXE、应用内升级或重新安装时，**只要保留同一系统用户的 LiteText 应用数据目录，配置就会保留**；主动清理用户数据、换系统账户或换电脑不在此范围。配置保留与 macOS 的系统隐私授权是两回事，后者仍可能再次询问。

| 操作 | macOS | Windows／Linux |
| --- | --- | --- |
| 新建 | Cmd+N | Ctrl+N |
| 打开 | Cmd+O | Ctrl+O |
| 保存 | Cmd+S | Ctrl+S |
| 关闭当前标签 | Cmd+W | Ctrl+W |
| 查找 | Cmd+F | Ctrl+F |
| 撤销 | Cmd+Z | Ctrl+Z |
| 注释／取消注释 | Cmd+/ | Ctrl+/ |
| 放大工作区 | Cmd++（也支持 Cmd+=） | Ctrl++（也支持 Ctrl+=） |
| 缩小工作区 | Cmd+- | Ctrl+- |
| 系统设置 | Cmd+, | Ctrl+, |

以上为默认绑定，完整列表及修改入口在「系统设置 → 快捷键」。

## 应用内更新

1. 打开「系统设置」，点击「检查更新」。
2. 如访问 GitHub 需要代理，启用专用代理并填写例如 `http://127.0.0.1:7890` 或 `socks5h://127.0.0.1:1080`。
3. 发现更高版本后，点击「下载更新」（稳定版不自动切到测试版；beta／rc 版可更新到后续预发布或稳定版）。
4. 下载、SHA-256 和版本校验通过后，关闭其他 LiteText 窗口，再点击「安装并重启」。

新版更新器直接使用 macOS DMG、Windows EXE、Linux ZIP，也兼容旧 ZIP 包。**旧版只识别 ZIP，切换到此版本时需要手动下载安装一次；安装新版后，后续可继续使用应用内升级。**

代理输入框以**明文**显示地址，**只用于 GitHub 更新检查和下载**，不是 GitHub 镜像 URL 前缀；关闭时直连，不使用环境代理。代理随设置保存但不加密，避免保存敏感凭据。

如果仓库只有 beta／rc 版本，没有稳定版，稳定安装版会提示「暂无稳定版」；未发布版本或缺少当前平台的完整更新包时会提示暂无可用版本，不再将这种情况显示为 `/releases/latest` 的 404 错误。

重启前会备份工作区；更新助手等待旧进程退出后替换程序，新版本未确认启动时尝试回退。请保持安装目录可写；macOS 不支持在 DMG 或 App Translocation 路径中原位更新。开发构建显示 `dev`，只能检查版本，不自动覆盖本地开发程序。

更完整的更新、安全边界与发布说明见 [docs/RELEASING.md](docs/RELEASING.md)。

## 从源码运行

安装 Rust stable 和平台构建工具后，在项目目录运行：

```sh
cargo run --locked
```

构建和检查：

```sh
cargo build --locked --release
cargo test --locked
cargo clippy --locked --all-targets -- -D warnings
```

macOS 需要 Xcode Command Line Tools；Windows 推荐 MSVC Rust 工具链和 Visual Studio C++ Build Tools；Ubuntu 的构建依赖可参考 [Release 工作流](.github/workflows/release.yml)。普通本地构建版本为 `dev`；发布版本由维护者手动推送 `v*` tag 后在 GitHub Actions 中注入，并自动生成 Release 产物。
