# LiteText 项目文档

> 轻量、快速、跨平台的文本/HEX 阅读器（Rust + egui）
> 最后更新：2026-11-12

## 项目简介

LiteText 是一个用 Rust 开发的跨平台（macOS / Windows / Linux）轻量级文本阅读编辑器，
设计目标是简洁、好看、高性能。支持文本编辑（UTF-8 / UTF-16）与二进制文件的
HEX 视图，带多标签页、主题切换、界面多语言与状态持久化。

## 技术栈

| 组件 | 选择 | 说明 |
|---|---|---|
| GUI | eframe / egui 0.31（glow） | 纯 Rust 原生渲染，无 WebView |
| 文件对话框 | rfd 0.15 | 原生对话框，多选 |
| 字体 | HarmonyOS Sans（内置）+ 系统字体回退 | 拉丁字形跨平台一致 |
| 序列化 | serde + serde_json | 配置持久化 / 窗口几何 |
| 字体解析校验 | ab_glyph 0.2 | 运行时校验系统字体可解析 |
| 原子写入 | tempfile 3.27 | 同目录临时文件 + sync + 原子替换 |

构建：`cargo run`（开发） / `cargo build --release`（已开 LTO + strip）。
测试：`cargo test`（143 个常规测试 + 2 个手动性能测试：用户日志与合成大文本）。

## 关键实现说明（踩坑与决策）

### 1. 中文字体垂直对齐（lineGap 内存补丁）
Hiragino Sans GB 的 `hhea.lineGap = 0.5em`，导致实现行高膨胀 1.5 倍，
egui 行盒居中时会把中文基线推高约 3pt（实测确认，表现为"中文比英文数字高"）。
**解法**：读入系统字体后在内存中把 hhea lineGap 置 0（`patch_cjk_line_gap`），
再用 `FontTweak.y_offset_factor = 0.04` 做光学微调。不要动这个补丁除非知道自己在做什么。

### 2. 字符间距测量必须用字形位置差
egui 对每个字形步进做物理像素取整（如 7.83pt → 8.0pt）。
用单字符 galley 宽度测出来的是未取整值，累计后 HEX 高亮与字形错位。
**解法**：`layout_no_wrap("0000000000")` 后取相邻字形 pos.x 差值。任何需要
等宽字符间距的地方（HEX 绘制、点击映射、Inspector 省略）都必须用同一测量。

### 3. 字体解析校验
egui 遇到非法字体数据会 panic。所有系统字体候选（中日文 + 符号字体）加载前
先用 ab_glyph 校验"能解析 + 包含目标字形"（中文字查 `中`，符号字体查 `␀`）。

### 4. HEX 视图坐标体系
- 表头渲染在 ScrollArea **外部**（天然冻结），与内容行共用同一字符宽度计算
- 每行内容为单个 LayoutJob（富文本着色），列对齐由等宽字体保证
- 点击命中：按字符列换算字节索引（每字节 3 字符，第 8 字节后 +1 中缝）

### 5. 标签页（槽位制绘制）
- 标签用手动槽位绘制（非顺序布局），拖拽 = 悬浮跟随指针 + 间隙槽动画滑动
- 纯函数 `layout_tab_xs` / `tab_slot_for_pointer` / `insert_id` / `tab_width_for`
  / `tab_fillet_shapes` 可单元测试（见 `cargo test`）
- 激活标签贯通顶栏底部，两侧外弯圆弧（`TAB_FILLET_RADIUS`，当前 8px），
  圆弧 = 矩形填充 + 打底圆盖出凹弧
- 右侧工具栏每帧实测宽度，标签区自适应

### 6. 自研组件（不依赖 egui 内置样式黑盒）
- **下拉框** `dropdown()`：芯片按钮 + 自绘弹层 + 点击外部关闭。
  egui 内置 ComboBox 的配色链路无法完全主题化，弃用
- **Inspector 拖宽**：egui SidePanel 的 resizable 分隔条会被内容组件抢事件，
  改为面板左缘自研拖拽条（`ui.interact` 注册在内容之上）

### 7. 文件解码
UTF-8（含 BOM）/ UTF-16LE/BE（带 BOM）；先识别 UTF-16 BOM，再按首 8KB 含 NUL 判断二进制。
未知字节有损显示，但手动保存拒绝有损覆盖，避免破坏原始编码。

### 8. 窗口几何
eframe 0.31 不自动持久化窗口大小位置。每帧跟踪 `viewport().outer_rect`，
退出时写入 `<storage_dir>/LiteText/window.json`，启动时经 ViewportBuilder 恢复。

### 9. 自动备份与手动保存分离
- 所有文本标签使用工作缓冲区，编辑不触碰原文件；每 5 秒及正常退出写入 `<eframe::storage_dir("LiteText")>/recovery/session.json`
- 恢复记录包含未命名/已修改文本与原文件基线；未修改标签只记录路径、顺序、视图，启动时重读磁盘
- 仅 Cmd+S / Ctrl+S（或关闭标签时选择保存）写入原文件；同目录临时文件写入并 sync 后原子替换，保留权限，符号链接写入真实目标
- 保存前比较磁盘内容与基线，发生外部修改时报错而非覆盖；编码不支持或非法时拒绝有损保存
- 恢复文件为本地明文，不是系统可清理的临时目录；异常退出最多可能丢失最近一个备份周期的输入；当前未实现多进程同时使用同一恢复记录的协调

### 10. 大文本与滚动条
- 先分配底部状态栏/HEX 工具栏，再创建中央编辑区，防止横向滚动条被覆盖；编辑器局部使用实体常显滚动条
- ≥256KB 的文本进入 `large_editor.rs`，缓存行字节索引，普通阅读只把可见行及上下各约 64 行交给 TextEdit 排版；编辑后写回完整工作缓冲区，再沿用原有恢复/手动保存流程
- 分段切换时利用每行缓存的字符起点与二分查找重映射光标，不再扫描全文前缀；普通编辑只重新扫描受影响逻辑行，后续行偏移在紧凑索引中平移
- 字符数与 UTF-16 编码大小按增删量更新，修改标记按版本号判断；保存后撤销/重做能正确切换修改状态（手动改回相同文字但未撤销时可保守显示为已修改）
- 大文本撤销历史保存 UTF-8 边界上的增删差量，最多 1000 条 / 16MiB（单次超大编辑为保留撤销能力可独占并超过预算），不再每次输入克隆全文；行号清空操作同样使用差量
- 大文本不再额外保留逐行字符串；编辑后 HEX 字节按需生成，切换 HEX / 手动保存仍需一次全量编码
- 恢复记录直接借用工作缓冲区流式序列化到原子临时文件，不再克隆全文/基线或创建完整 JSON 字节数组；无变更周期跳过写入，记录被外部删除/修改时重新写入并保留损坏记录。仍在 UI 线程执行，发生修改的超大恢复记录写入仍可能有停顿
- 仍全量读入文件并保留磁盘基线；字符串中部插入需移动后缀，索引更新也随后续行数增长。首次索引、超长单行、跨很大范围的文本选区（含全选）和超大文件仍有开销；不是分页磁盘编辑器
- 手动性能测试：`LITETEXT_BENCH_FILE=/path/to/file cargo test --locked benchmark_user_log_editor -- --ignored --nocapture`，只在内存里编辑并校验原文件不变
- 合成大文本测试：`cargo test --locked benchmark_large_incremental_edits -- --ignored --nocapture`，测试 3/32/128MiB 内存文本的中部插入，不写用户文件
